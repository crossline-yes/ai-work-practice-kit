# AI와 프로젝트를 진행하는 설명서

## 요청 하나의 기본 구조

**목표 + 참고 파일·현재 상태 + 필수 조건 + 이번 작업 범위 + 확인 방법**을 전달합니다. 경로나 오류를 모르면 먼저 찾게 하세요. 모든 내용을 한 번에 요구할 필요는 없습니다.

## 자료를 읽는 단계

README와 과제 지시, 데이터 설명, 기존 코드를 우선합니다. 각 파일의 역할·단위·기준 시점·연결 키·중복·누락을 확인합니다. 한 행이 개인인지 집단인지, 이미 집계한 수치인지 확인하고 같은 자료의 CSV·JSON 표현을 중복 집계하지 않습니다. 접근하지 못한 파일을 읽었다고 취급하지 않습니다.

## 업무 담당자에게 질문하는 단계

사용자, 해결하려는 불편, 필요한 입력과 결과, 필수 조건, 조건 충돌 시 우선순위, 완료 기준을 확인합니다. 질문마다 왜 필요한지 알고 묻습니다. 결정된 규칙, 담당자의 의견, 본인 제안, 아직 모르는 사실을 구분합니다. 답이 이미 자료에 있으면 반복 질문보다 그 내용을 확인해 정리합니다.

## 구현 단계

기존 프로젝트 구조, 실행 명령, 제공 도구·라이브러리를 확인합니다. 새 기술을 추가할 때는 현재 환경·설치 시간·외부 통신·재현성을 살펴봅니다. 입력 읽기와 작은 결과 표시부터 작동시킨 뒤 기능을 확장합니다. 실제 데이터를 코드 안에 결과값으로 고정하지 않습니다. 계산과 출력의 구분이 설명 가능하도록 요청하세요.

## 실행 화면이 안 보일 때

1. 정확한 실행 명령과 오류 확인.
2. 서버가 실제 실행 중인지, 주소와 포트가 무엇인지 확인.
3. 해당 플랫폼의 미리보기 연결 방법으로 열기.
4. 포트를 임의로 여러 개 만들기 전에 기존 프로세스 확인.
5. 새로고침 후 유지·초기화되어야 할 상태 확인.

연습 사이트의 단일 HTML Browser와 서버를 실행하는 실제 프로젝트는 실행 방식이 다를 수 있습니다. 특정 포트·배포 방식이 모든 환경에서 통한다고 가정하지 않습니다.

## 검증 단계

정상 입력, 정확한 경계, 잘못된 입력, 누락·중복, 데이터 변경, 정상 처리 후 오류 입력, 저장·다운로드 일치를 확인합니다. 요구사항마다 입력·예상·실제 결과를 남기고 코드 검토와 실제 실행을 구분합니다. 가능하면 작은 사례 하나를 사람이 직접 대조합니다. AI에게 검사 결과를 만들라고 요청하지 말고 실제 수행하도록 합니다.

## 공개 코드 사용 단계

`prompts/07-public-code.md`를 사용합니다. 공식 문서·LICENSE·의존성·설치 가능성을 확인하고 필요한 부분을 설명받습니다. 가져온 출처·버전 또는 Commit·사용한 부분·직접 바꾼 부분·검증을 기록합니다. 설치만으로 기능이 완성되었다고 판단하지 않습니다. 검증 없는 최적·정확·안전 주장을 피합니다.

## 제출 단계

필수 파일·파일명·경로·실행 방법을 대조합니다. 마지막 수정 후 필요한 검사를 다시 확인합니다. 완성 범위와 남은 한계, 담당자가 쓸 순서를 정리합니다. 실제 제출 버튼과 후속 단계 완료 여부는 해당 플랫폼 안내로 확인합니다.

## 설명 단계

결과물의 각 기능을 본인의 코드·자료·실행 사례와 연결합니다. AI가 선택한 방법도 이해되지 않는다면 작은 입력을 따라가며 설명해 달라고 요청하고 직접 확인합니다. 조건 변경의 영향을 계산·입력·화면·검증으로 나눠 생각합니다. 후속 연습은 사전 학습용이며 실제 응시 중 AI를 호출하는 방법이 아닙니다.
