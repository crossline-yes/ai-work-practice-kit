# 07. 공개 코드와 도구 검토하기

대상: 작업용 AI. 현재 환경에서 외부 자료를 가져오는 것이 허용된 경우 사용합니다. 공개 저장소라는 이유만으로 모든 사용이 허용되지는 않으므로 라이선스와 현재 과제의 이용 조건을 확인합니다.

```text
현재 [필요한 기능]에 공개 코드나 라이브러리를 활용할지 검토해줘.
직접 구현하는 방법과 공개 도구를 적용하는 방법을 비교해줘.

후보가 필요하면 적은 수만 찾고 다음을 확인해줘.
1. 원본 저장소·문서 URL과 사용할 버전 또는 커밋
2. 라이선스, 고지·출처 표시 등 확인할 이용 조건
3. 현재 실행 환경과의 호환성, 설치·학습·연결에 드는 시간
4. 필요한 기능과 실제 제공 기능의 차이
5. 입력·출력 형식, 데이터 전송 여부, 필요한 계정·외부 서비스
6. 적용 후 확인해야 할 정상·예외 사례

읽어보지 않은 저장소를 사용 가능하다고 단정하지 마.
현재 과제의 도구·네트워크·외부 전송 제한을 지켜줘.
접근할 수 없는 링크는 접근하지 못했다고 알려줘.
현재 자료·코드·결과물을 외부로 전송하지 마.

먼저 검토 결과와 추천을 알려줘. 아직 설치하거나 코드를 가져오지 마.
```

검토 후 사용하기로 결정했다면:

```text
[후보와 버전]의 [필요한 부분]을 적용해줘.
이용 조건을 따르고 원본 출처·사용 버전·적용 위치를 기록해줘.
우리 입력과 업무 규칙에 맞게 연결하고 실제 동작을 확인해줘.
외부에서 가져온 부분, 직접 작성·수정한 부분, 남은 한계를 구분해 설명해줘.
원래 요구사항과 무관한 완성품으로 전체 결과물을 대체하지 마.
```

내가 설명할 수 있어야 하는 것:

- 이 도구가 해결하는 정확한 부분은 무엇인가?
- 입력과 반환 결과를 우리 서비스에 어떻게 연결했는가?
- 원본 예제와 우리 과제의 조건 차이는 무엇인가?
- 직접 구현보다 이 방법을 고른 이유와 검증 근거는 무엇인가?
